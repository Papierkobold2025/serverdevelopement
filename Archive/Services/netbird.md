# NetBird Service Integration

- Installation of NetBird to replace WireGuard with a panel-managed application.

## Decisions

- Replace the Nextcloud Talk port 3478 with NetBird using the standard installation package configuration.

- Replace the connection port 8081 with port 80 because that is the port where the Docker host listens.

- Edit the network parameters at the server level using `network_mode: host` to accept network traffic received by the container.

- Add the Pi-hole IP to the configuration as `trustedHTTPProxies` to allow DNS name resolution.

- Separate Realms for administration and user access.

- Install Quick Install to avoid configuring four separate Docker containers.

### Issues encountered

- A peer could not talk to another peer on the LAN due to the NetBird configuration: lazy connection, where if there is no network traffic between the two peers, the handshake is not established.

    - Solution: pinging a peer on the LAN immediately activated the connection.

### Runbook

- NetBird installation script

    - ```bash curl -fsSL https://github.com/netbirdio/netbird/releases/latest/download/getting-started.sh | bash ```

- ~/docker-compose.yml

```bash
services:
  # UI dashboard
  dashboard:
    image: netbirdio/dashboard:latest
    container_name: netbird-dashboard
    restart: unless-stopped
    networks: [netbird]
    ports:
      - '0.0.0.0:8080:80'
    env_file:
      - ./dashboard.env
    logging:
      driver: "json-file"
      options:
        max-size: "500m"
        max-file: "2"
  # Combined server (Management + Signal + Relay + STUN)
  netbird-server:
    image: netbirdio/netbird-server:latest
    container_name: netbird-server
    restart: unless-stopped
    network_mode: host
    cap_add:
      - NET_ADMIN
    volumes:
      - netbird_data:/var/lib/netbird
      - ./config.yaml:/etc/netbird/config.yaml
    command: ["--config", "/etc/netbird/config.yaml"]
    logging:
      driver: "json-file"
      options:
        max-size: "500m"
        max-file: "2"
volumes:
  netbird_data:
networks:
  netbird:
```

- ~/config.yaml

```bash
# Combined NetBird Server Configuration (Simplified)
# Generated by getting-started.sh

server:
  listenAddress: ":80"
  exposedAddress: "https://netbird.network.mydomain.com:443"
  stunPorts:
    - 3478
  metricsPort: 9090
  healthcheckAddress: ":9000"
  logLevel: "info"
  logFile: "console"

  authSecret: "authSecret"
  dataDir: "/var/lib/netbird"

  auth:
    issuer: "https://netbird.network.mydomain.com/oauth2"
    signKeyRefreshEnabled: true
    dashboardRedirectURIs:
      - "https://netbird.network.mydomain.com/nb-auth"
      - "https://netbird.network.mydomain.com/nb-silent-auth"
    cliRedirectURIs:
      - "http://localhost:53000/"

  reverseProxy:
    trustedHTTPProxies:
      - "192.168.X.X/32"

  store:
    engine: "sqlite"
    encryptionKey: "encryptionKey"
```

- NGINX configuration so that the peers work correctly

```bash
client_header_timeout 1d;
client_body_timeout 1d;

location ~ ^/(relay|ws-proxy/) {
    proxy_pass http://192.168.X.X:80;
    proxy_http_version 1.1;
    proxy_set_header Upgrade $http_upgrade;
    proxy_set_header Connection "upgrade";
    proxy_set_header Host $host;
    proxy_set_header X-Real-IP $remote_addr;
    proxy_set_header X-Forwarded-For $proxy_add_x_forwarded_for;
    proxy_set_header X-Forwarded-Proto $scheme;
    proxy_read_timeout 1d;
}

location ~ ^/(signalexchange\.SignalExchange|management\.ManagementService)/ {
    grpc_pass grpc://192.168.X.X:80;
    grpc_read_timeout 1d;
    grpc_send_timeout 1d;
    grpc_socket_keepalive on;
}

location ~ ^/(api|oauth2)/ {
    proxy_pass http://192.168.X.X:80;
    proxy_set_header Host $host;
    proxy_set_header X-Real-IP $remote_addr;
    proxy_set_header X-Forwarded-For $proxy_add_x_forwarded_for;
    proxy_set_header X-Forwarded-Proto $scheme;
}
```

- Once the configurations are complete, the network inside NetBird itself still has to be adjusted to mask traffic and create network access routes through peers.
